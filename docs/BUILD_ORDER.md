## 나누는 원칙

1. **화면 흐름으로 3개 레인을 나눈다.** 방, 지출, 보드. 한 사람이 자기 레인의 화면, API, DB 조회까지 전부 만든다.
2. **자기 레인 폴더만 고친다.** 다른 레인의 파일은 읽기만 한다.
3. **공용 파일은 S0에서 한 번에 만든다.** 그 뒤로는 안정훈만 별도 PR로 고친다.
4. **레인끼리는 약속으로만 만난다.** 약속은 주소(URL), 테이블, 계산식 세 가지다.
5. **데모 방을 미리 넣어 둔다.** 방 레인이 끝나지 않아도 지출과 보드 레인이 바로 개발할 수 있다.

## 기술 스택 🟡

| 부분 | 제안 | 이유 |
|---|---|---|
| 서버 | FastAPI (Python) | 오픈뱅킹 `client_secret`을 서버 안에 숨겨야 한다 |
| 화면 | HTML + JavaScript (빌드 단계 없음) | 설정이 적어 막힐 곳이 적다 |
| DB | 외부 Postgres (예: Supabase 무료) | 챌린지 기간 동안 데이터가 남아야 한다 |
| 배포 | Render 웹 서비스 | 수업에서 쓰는 방식 |

- 확인 필요: Render 무료 서버가 한동안 요청이 없으면 잠드는지(발표 직전에 미리 열어 둔다), Supabase 무료 요금제의 제한과 Render에서 접속되는 연결 주소.
- 스택을 바꿔도 레인과 약속은 그대로 쓴다. 폴더 이름만 바뀐다.

## 약속 (contract)

### 주소

| 주소 | 화면 | 레인 |
|---|---|---|
| `/` | 방 만들기 | 방 |
| `/r/{code}` | 방 홈. 보드가 먼저 보이고 그 자리에서 참여 | 방 (보드 부분은 보드 레인의 API를 쓴다) |
| `/r/{code}/add` | 지출 올리기 (계좌 연결, 확인 화면) | 지출 |
| `/r/{code}/board` | 남은 예산 보드, 결과 카드 | 보드 |

API는 레인 이름으로 시작한다: `/api/rooms/...` `/api/expenses/...` `/api/board/...`

오픈뱅킹 관련 주소 🟡 (지출 레인):

| 주소 | 하는 일 |
|---|---|
| `GET /api/expenses/bank/connect?member_id=` | 계좌 연결 시작. 테스트베드 사용자인증 페이지로 보낸다 |
| `GET /api/expenses/bank/callback` | 콜백. 인증 코드를 토큰으로 바꿔 저장한다. 테스트베드에 등록하는 콜백 주소(`OB_CALLBACK_URL`)가 이것이다 |
| `GET /api/expenses/bank/transactions?member_id=` | 거래내역을 불러와 출금만 지출 형식으로 돌려준다 |

### 테이블

| 테이블 | 칸 | 쓰는 레인 |
|---|---|---|
| `rooms` | code, name, start_date, end_date, upload_cycle, deadline_weekday | 방 |
| `members` | id, room_code, nickname, budget | 방 |
| `expenses` | id, member_id, spent_on, merchant, amount, people, excluded, source, category | 지출 |
| `bank_links` 🟡 | member_id, access_token, refresh_token, user_seq_no, fintech_use_num, expires_at | 지출 (만드는 것은 안정훈) |

- 보드 레인은 `rooms` `members` `expenses`를 읽기만 한다. `bank_links`는 지출 레인만 읽고 쓴다.
- `source`는 `bank`(테스트베드) 또는 `manual`(직접 입력, 예비)이다.
- `category`는 비워 둔다. 카테고리화는 10/8 이후다.
- 로그인이 없으므로 "나"는 브라우저에 저장한 멤버 id로 구분한다. 저장 이름은 `member_id:{code}`다.
- `bank_links`의 칸 이름은 테스트베드 명세서를 확인한 뒤 이태윤이 확정해 안정훈에게 알린다.

### 환경변수

| 이름 | 내용 |
|---|---|
| `DATABASE_URL` | 외부 Postgres 연결 주소 |
| `OB_CLIENT_ID` | 테스트베드 앱의 client_id |
| `OB_CLIENT_SECRET` | 테스트베드 앱의 client_secret |
| `OB_CALLBACK_URL` | 테스트베드에 등록한 콜백 주소 |
| `OB_ORG_CODE` | 이용기관코드 |
| `OB_MOCK` | `1`이면 모의 모드. 테스트베드를 부르지 않고 같은 형식의 예시 거래내역을 돌려준다 |

실제 값은 Render와 각자의 `.env`에만 넣는다. 레포에는 이름만 있는 `.env.example`을 올린다.

### 계산식

- 내 몫 = `amount ÷ people`
- 쓴 돈 = 제외하지 않은 항목의 내 몫 합계
- 남은 예산 = `budget − 쓴 돈`
- 사용률 = `쓴 돈 ÷ budget`
- 순위 = 사용률이 낮은 순
- 초과 = 남은 예산이 0보다 작다
- 미제출 = 마감까지 그 주기에 저장한 지출이 없다

## 순서

### S0 뼈대 (안정훈, 10/2)

- 브랜치: `feat/s0-ahn`
- 만드는 것: 폴더 구조, 공용 파일 전부, 빈 화면과 빈 API, 테이블(`bank_links` 포함), 데모 방(`/r/demo`, 예시 멤버 3명과 지출 몇 건), Render 배포
- `requirements.txt`에는 뒤에서 쓸 패키지까지 미리 넣는다 (테스트베드를 부를 HTTP 클라이언트 포함)
- 끝나는 조건: 배포 URL에서 빈 화면이 열리고, 데모 방 데이터가 DB에서 읽힌다
- 끝나면 바로: 배포 주소를 이태윤에게 전달한다 (콜백 주소 등록용). 기술 스택을 팀에 공유한다
- 그동안 이태윤: 테스트베드 가입, 앱 등록, 테스트 데이터 입력
- 그동안 김경은: 보드 화면 구성 스케치 (단순화)

### S1 개발 (3명 동시, 10/3 ~ 10/4)

| 슬라이스 | 브랜치 | 만드는 것 |
|---|---|---|
| S1-방 | `feat/s1-room-ahn` | 방 만들기(기간, 업로드 주기, 마감 요일) → 링크 생성 → 링크에서 닉네임과 예산으로 참여 |
| S1-지출 | `feat/s1-expense-lee` | 계좌 연결 → 토큰 저장 → 거래내역 불러오기 → 확인 화면 → 저장. 모의 모드 |
| S1-보드 | `feat/s1-board-kim` | 멤버별 남은 예산 막대, 순위, 초과·미제출 표시, 지난 기간 세로선, 결과 카드 |

S1-지출의 확인 화면에 포함되는 것: 입금 무시, 가승인 자동 제외, 내 계좌 간 이체와 충전은 제외 후보 표시, 기간 밖 날짜 자동 제외, 중복 경고(날짜 · 상호 · 금액이 같을 때).

S1-지출은 모의 모드부터 만든다. 테스트베드가 막혀도 화면과 저장을 먼저 끝낼 수 있다.

### 합치기와 점검 (10/5 ~ 10/6)

- 10/5: 각자 PR을 main에 합치고, 배포 URL에서 전체 흐름을 한 번에 확인한다
- 10/6: 버그 수정. 모의 모드를 켜고 같은 흐름을 다시 확인한다. 여유가 있으면 "무엇을 받고 무엇을 저장하지 않는지" 안내 문구를 넣는다

## 충돌을 막는 규칙

- 작업을 시작하기 전에 `git pull` 한다.
- 자기 브랜치에서만 작업한다. main에 직접 push 하지 않는다.
- 완료하면 PR → 팀원 1명 확인 → merge. PR은 작게 만들고 하루에 한 번 이상 merge 한다.
- 공용 파일을 고쳐야 하면 단톡방에 먼저 말한다. 안정훈이 별도 PR로 고치고 나머지는 pull 한다.
- 약속을 바꿀 때는 이 문서를 먼저 고친다.
- `.env`, `client_secret`, 토큰은 커밋하지 않는다. 이 레포는 공개 레포다.
- 중간 보고 시점과 방식은 팀이 정한다 (예: 매일 저녁 단톡방에 한 줄).
