# Claude Code 지시문

자기 이름의 지시문을 Claude Code에 그대로 붙여 넣는다.
프로젝트 폴더(`SPAN-team`)에서 Claude Code를 연 상태여야 한다. `CLAUDE.md`는 Claude Code가 자동으로 읽는다.

순서: **① 안정훈(S0 뼈대)** 이 끝나고 main에 합쳐진 뒤에 ②③④를 시작한다.

오픈뱅킹은 이용 자격이 없어 뺐다. 지출은 서버에 넣어 둔 가상 계좌 데이터로 불러온다.

---

## ① 안정훈 · S0 뼈대와 배포 (10/2)

```
나는 안정훈이고, 이 프로젝트의 뼈대(S0)와 공용 파일 담당이야.
CLAUDE.md, docs/PRD.md, docs/BUILD_ORDER.md를 먼저 읽어줘.

오늘 목표는 팀원 두 명이 내일부터 각자 레인을 바로 개발할 수 있는 뼈대를 만들고 Render에 배포하는 거야.
기능은 비어 있어도 되고, "배포까지 끝내는 것"이 우선이야. 배포에서 막히는 문제를 마감 직전이 아니라 오늘 만나려는 거야.

feat/s0-ahn 브랜치에서 작업해줘 (없으면 만들고). 만들 것:

1. 폴더 구조: BUILD_ORDER.md의 레인별 폴더(app/rooms, app/expenses, app/board와 각 static, tests)와 공용 파일 전부.
2. app/main.py: 레인별 라우터 3개를 붙이고 static을 서빙. 각 레인 폴더에는 라우터 파일과 빈 화면(HTML)만 넣어서, 팀원이 자기 폴더 안에서만 작업해도 되게 해줘.
3. 빈 화면과 빈 API: /, /r/{code}, /r/{code}/add, /r/{code}/board 가 열리고, /api/rooms, /api/expenses, /api/board 가 각각 응답하게.
4. db/schema.sql: rooms, members, expenses 테이블. 칸은 BUILD_ORDER.md의 "테이블"을 따라줘. expenses.source는 virtual, manual, file 중 하나이고, 같은 멤버가 같은 ref를 두 번 저장하지 못하게 해줘 (ref가 비어 있는 직접 입력은 여러 건 가능해야 해).
5. db/seed.sql: 데모 방(code = demo), 예시 멤버 3명(예산이 서로 다르게), 지출 몇 건. 보드에서 초과와 미제출이 둘 다 보이도록 한 명은 예산을 넘기고 한 명은 지출이 없게 해줘. 데모 방의 기간은 오늘이 그 안에 들어가게 잡아줘.
6. app/db.py: DATABASE_URL 환경변수로 외부 Postgres에 연결. 스키마와 시드를 넣는 방법(명령어 한 줄)도 만들어줘.
7. requirements.txt: 나중에 팀원이 이 파일을 고칠 일이 없게, 파일 업로드를 만들 경우 필요한 패키지(업로드 처리, 엑셀 읽기)까지 미리 넣어줘.
8. render.yaml과 README의 배포 주소 칸.
9. static/common.css: 세 화면이 같이 쓸 최소한의 스타일만. 단순하게.

.env.example, .gitignore, CLAUDE.md, README.md, docs는 이미 있으니 필요한 부분만 고쳐줘.
외부 API는 하나도 쓰지 않아. 환경변수는 DATABASE_URL 하나뿐이야.

진행 방식:
- 나는 개발 입문자야. 내가 직접 해야 하는 일(Supabase에서 DB 만들기, Render에 연결하기, 환경변수 넣기)은 클릭 순서대로 하나씩 알려주고, 내가 끝냈다고 하면 다음으로 넘어가줘.
- 로컬에서 uvicorn으로 띄워 네 주소가 열리고 /r/demo 데이터가 DB에서 읽히는 걸 확인한 다음에 배포로 넘어가줘.
- Render에서 Supabase에 접속이 안 되면 연결 주소 종류(직접 연결 / pooler) 문제일 수 있으니 그것부터 확인해줘.
- 비밀값은 코드와 커밋에 넣지 마. 레포가 공개야.

끝나는 조건: 배포 URL에서 네 화면이 열리고, /r/demo 의 멤버와 지출이 DB에서 읽혀 화면이나 API 응답에 보인다.
끝나면 PR을 만들고, 팀 단톡방에 올릴 메시지(배포 주소, 확정된 기술 스택, 로컬 실행 방법, .env 값을 받는 방법)를 써줘.
```

## ② 안정훈 · S1 방 레인 (10/3 ~ 10/4)

```
나는 안정훈이고 방 레인 담당이야. CLAUDE.md, docs/PRD.md, docs/BUILD_ORDER.md를 읽어줘.
main을 pull 한 뒤 feat/s1-room-ahn 브랜치에서 작업해줘. app/rooms/, static/rooms/, tests/rooms/ 만 고쳐.

만들 것:
1. 방 만들기(/): 방 이름, 기간(시작일·종료일), 업로드 주기(기본 주 1회), 마감 요일을 넣으면 방이 만들어지고 공유할 링크(/r/{code})가 보인다. 링크 복사 버튼.
2. 방 홈(/r/{code}): 링크로 들어오면 보드가 먼저 보이고, 그 자리에서 닉네임과 내 예산만 넣어 참여한다. 로그인은 없다.
   - 참여하면 멤버 id를 브라우저 localStorage에 `member_id:{code}` 이름으로 저장한다. 지출과 보드 레인이 이 값을 읽는다.
   - 이미 참여한 사람이 다시 들어오면 참여 폼 대신 "지출 올리기"(/r/{code}/add)와 "보드"(/r/{code}/board)로 가는 버튼을 보여준다.
   - 보드 부분은 직접 계산하지 말고 보드 레인의 API(/api/board/...)를 불러서 그려줘. 보드 API가 아직 없으면 멤버 목록만 보여주고, 나중에 바꿀 자리를 표시해 둬.
3. 없는 방 코드로 들어오면 안내 화면.

끝나는 조건: 방을 만들면 링크가 생기고, 다른 브라우저(시크릿 창)에서 그 링크로 들어와 닉네임과 예산을 넣으면 참여된다.
화면은 단순하게. 한 기능이 끝날 때마다 내가 브라우저에서 확인할 방법을 알려줘.
```

## ③ 이태윤 · 지출 (가상 계좌)

### 뼈대 전에 할 일 (Claude Code 없이, 지금 바로)

가상 계좌 3개의 거래내역을 표로 적어 둔다 (메모장이나 스프레드시트). 계좌마다 10건 안팎이면 충분하다.

- 계좌마다 성격을 다르게: 아껴 쓰는 사람, 보통, 많이 쓰는 사람. 보드에서 순위 차이가 나야 한다.
- 꼭 들어가야 하는 거래: 학생식당 결제, 같은 결제 두 번, 택시 가승인, 충전, 내 계좌 간 이체, 입금 1건, 기간 밖 날짜 1건, 여럿이 같이 낸 식비, 월세나 통신비.
- 날짜는 "기간 시작 후 며칠째"로 적는다 (예: 1일째, 3일째).
- 실제 은행 이름은 쓰지 않는다 (예: "가상 계좌 A").

### 지시문 (10/3 ~ 10/4)

```
나는 이태윤이고 지출 레인 담당이야. CLAUDE.md, docs/PRD.md, docs/BUILD_ORDER.md를 읽어줘.
main을 pull 한 뒤 feat/s1-expense-lee 브랜치에서 작업해줘. app/expenses/, static/expenses/, tests/expenses/ 만 고쳐.

배경: 원래는 오픈뱅킹으로 실제 거래내역을 가져오려 했는데, 승인받은 기관만 이용할 수 있어서 뺐어.
대신 서버에 넣어 둔 가상 계좌 데이터를 "계좌 연결" 한 번으로 불러오는 방식으로 만들 거야. 외부 API는 부르지 않아.

목표: /r/{code}/add 에서 "계좌 연결" → 가상 계좌 선택 → 거래내역을 확인 화면에 표시 → 항목마다 몇 명이서·제외 선택 → 저장 → 보드에 반영.

이 순서로 해줘:

1단계. 가상 계좌 데이터
- app/expenses/ 안에 가상 계좌 3개의 거래내역 파일을 만들어줘. 내가 미리 적어 둔 시나리오를 아래에 붙일게.
  [여기에 적어 둔 거래내역 표를 붙인다. 없으면 PRD 6번의 시연 시나리오로 만들어 달라고 한다]
- 날짜는 "기간 시작 후 며칠째"로 저장하고, 불러올 때 방의 start_date에 맞춰 실제 날짜로 바꿔줘. 어느 방에서 불러와도 기간 안에 들어오게 (기간 밖 거래 1건은 일부러 밖에 있게).
- 거래마다 고유 번호(ref)를 줘.
- 가상 계좌 목록 API와 거래내역 API를 만들어줘. 주소는 BUILD_ORDER.md의 "가상 계좌 관련 주소"를 따르되, 더 나은 형태가 있으면 제안해줘.
- 거래내역을 가져오는 부분은 함수 하나로 분리해줘. 나중에 실제 계좌 연결로 바꿀 때 그 함수만 바꾸면 되게.

2단계. 확인 화면과 저장
- 출금만 보여주고 입금은 무시.
- 가승인은 자동 제외, 내 계좌 간 이체와 충전은 "제외 후보"로 표시, 방의 기간 밖 날짜는 자동 제외, 날짜·상호·금액이 같으면 중복 경고.
- 항목마다 "몇 명이서"(기본 1)와 "제외" 버튼. 저장하면 expenses 테이블에 source = virtual 로 들어간다.
- 같은 거래를 두 번 저장하지 않게 해줘 (ref로 구분). 이미 저장한 거래는 다시 불러왔을 때 "저장됨"으로 보여줘.
- "나"는 localStorage의 `member_id:{code}` 로 구분한다. 없으면 방 홈(/r/{code})으로 보내 참여하게 한다. 개발 중에는 데모 방(/r/demo)의 멤버로 확인해줘.
- 여기까지 되면 PR을 한 번 올려줘. 보드 담당이 실제 저장 데이터로 확인할 수 있게.

3단계. 직접 입력 (예비)
- 같은 화면 아래에 날짜, 상호, 금액, 몇 명이서를 직접 넣는 작은 폼. source = manual. 가상 계좌에 없는 실제 지출을 넣을 때 쓴다.

4단계. 다듬기
- 화면에 "시연용 가상 계좌입니다. 실제 계좌와 연결되지 않습니다"를 눈에 띄지만 방해되지 않게 적어줘.
- "계좌 연결"을 눌렀을 때 실제 은행 로고나 은행 이름은 쓰지 마.
- 저장 후에는 보드(/r/{code}/board)로 가는 버튼을 보여줘.

파일 업로드(은행에서 받은 엑셀을 올려 인식)는 여기까지 끝나고 시간이 남을 때만 할 거야. 지금은 만들지 마.

schema.sql의 테이블 칸이 부족하면 직접 고치지 말고, 바꿔야 할 내용을 정리해서 알려줘. 내가 안정훈에게 전달할게.

끝나는 조건: 배포 URL의 새 방에서 계좌 연결부터 저장까지 되고, 저장한 뒤 보드의 내 남은 예산이 바뀐다.
나는 개발 입문자야. 단계마다 내가 브라우저에서 확인할 방법을 알려주고, 막히는 부분은 숨기지 말고 바로 말해줘.
```

- 양식이 다르거나 읽지 못하면 이유를 화면에 보여줘.

## ④ 김경은 · 보드 (10/3 ~ 10/4)

```
나는 김경은이고 보드 레인 담당이야. CLAUDE.md, docs/PRD.md, docs/BUILD_ORDER.md를 읽어줘.
main을 pull 한 뒤 feat/s1-board-kim 브랜치에서 작업해줘. app/board/, static/board/, tests/board/ 만 고쳐.

목표: /r/{code}/board 에서 방 멤버들의 남은 예산을 한눈에 보여주는 보드와, 마감 후 결과 카드.
다른 레인이 끝나지 않아도 되도록 데모 방(/r/demo) 데이터로 개발해줘. 보드는 rooms, members, expenses 테이블을 읽기만 해.

만들 것:
1. 보드 API(/api/board/{code}): 멤버별 예산, 쓴 돈, 남은 예산, 사용률, 순위, 초과 여부, 미제출 여부를 돌려준다. 계산식은 BUILD_ORDER.md의 "계산식"을 그대로 따라줘. 방 홈(/r/{code})도 이 API를 쓰니까 응답 형식을 정하면 나한테 알려줘. 방 담당에게 전달할게.
2. 보드 화면: 맨 위에 "내 남은 예산"을 크게, 그 아래 멤버별 막대와 순위. "나"는 localStorage의 `member_id:{code}` 로 구분하고, 없으면 내 영역 없이 전체만 보여준다.
3. 표시: 예산을 넘긴 멤버는 탈락이 아니라 "초과"로, 마감까지 안 올린 멤버는 "미제출"로. 막대에는 기간이 얼마나 지났는지 알려주는 세로선.
4. 결과 카드: 방의 종료일이 지나면 순위와 각자의 결과를 보여주는 카드. 발표 때 보여줄 수 있게, 종료일이 지나지 않은 방에서도 결과 카드를 미리 볼 방법을 하나 만들어줘.
5. 친구에게는 합계와 남은 예산만 보인다. 거래 항목(상호, 개별 금액)은 보드에 절대 내보내지 마. API 응답에도 넣지 마.

화면은 최대한 단순하게 해줘. 멘토 피드백이 "UI가 너무 복잡하다"였고, 이 화면이 그 피드백을 가장 많이 받는 곳이야. 한 화면에 숫자와 장식을 늘리지 말고, 3초 안에 "내가 얼마 남았고 몇 등인지"가 보이는 것을 기준으로 해줘. 휴대폰 화면 폭에서 먼저 확인해줘.

전체적인 UI 톤(색, 글꼴, 버튼 모양)을 제안하고 싶으면 static/common.css를 직접 고치지 말고 static/board/ 안에서 먼저 만들어 보여줘. 괜찮으면 내가 안정훈에게 공용으로 옮겨 달라고 할게.

끝나는 조건: /r/demo/board 에서 멤버별 남은 예산 막대, 순위, 초과·미제출 표시, 결과 카드가 보인다.

## 공통 · 작업을 마칠 때

```
지금까지 한 작업을 커밋하고 PR을 만들어줘.
커밋 전에 확인해줘: 내 레인 폴더 밖의 파일을 고치지 않았는지, 비밀값이나 실제 거래내역이 들어가지 않았는지, 로컬에서 실행해 화면이 열리는지.
PR 설명에는 무엇을 만들었는지, 팀원이 어떻게 확인하면 되는지, 아직 안 된 것을 써줘.
그리고 단톡방에 올릴 한 줄 중간 보고를 써줘.
```

## 공통 · 10/5 합친 뒤 점검

```
main을 pull 해서 전체 흐름을 처음부터 확인해줘: 새 방 만들기 → 링크로 참여(멤버 3명) → 각자 다른 가상 계좌 연결 → 확인 화면 → 저장 → 보드 갱신 → 결과 카드.

내 레인의 문제만 고치고, 다른 레인의 문제는 담당자에게 전달할 내용으로 정리해줘.
