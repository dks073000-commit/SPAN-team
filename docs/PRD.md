> 대학생이 친구들과 예산을 걸고, 각자 남은 돈을 한 화면에서 같이 보는 웹서비스.
> 원본은 Notion "01 기획" 페이지이고, 이 파일은 2026-10-03 기준이다.
> 10/2 변경: 오픈뱅킹은 승인받은 기관(핀테크 사업자 · 전자금융업자)만 이용할 수 있어 제외했다. 지출 입력은 가상 계좌로 한다. 캡처 인식도 하지 않는다.

## 팀이 정한 것

- **입력** 🟢: 참여할 때 은행 연결 → 내 계좌 선택(가짜 은행 화면 안)을 하고, 본인 페이지에서 그 계좌의 거래내역을 불러온다 (10/3). 직접 입력은 예비로 둔다. 거래내역 파일 업로드는 시간이 남을 때만 한다
- **하지 않는 것** 🟢: 캡처 인식 (10/1 결정), 오픈뱅킹 연동 (10/2, 이용 자격 없음)
- **공동계산** 🟢: 금액마다 "몇 명이서"만 선택한다. 금액 ÷ 인원만 내 지출로 잡는다
- **업로드 주기 · 마감 요일**: 미제출이 없어져 쓰지 않는다 (10/3). 마감은 방의 종료일 하나다. DB 칸은 남겨 두고, 방 만들기 화면은 김경은 디자인에 맞춰 나중에 정리한다
- **예산** 🟢: 각자 정하는 대로 넣는다
- **예산을 넘기면** 🟢: 탈락이 아니라 초과 표시 + 순위
- **미제출** 🟢: 두지 않는다 (10/3). 참여할 때 은행 연결 → 내 계좌 선택(가짜 은행 화면 안)을 마쳐야 하므로 "안 올린" 상황이 없고, 마감 때 아직 안 불러온 사람의 내역은 자동으로 채운다
- **미확인** 🟢: 항목 조정(1/N · 제외)을 안 한 상태. 불러온 금액이 전부 반영된다. 조정을 마친 뒤 새 지출이 들어오면 다시 미확인이 된다. 결과 페이지로 가려면 조정을 거쳐야 한다 (10/3)
- **중도포기** 🟢: 본인 페이지의 항복 버튼. 되돌릴 수 없다. 결과에서 항복 깃발로 표시하고 금액은 숨긴다. 먼저 포기한 사람이 맨 아래 (10/3)
- **보드 구조** 🟢: 기간 중에는 팀 차트 없이 본인 페이지만 (불러오기 · 1/N · 제외 · 목표까지 남은 금액). 방 홈에는 참여자 이름만. 순위는 마감일 결과 카드에서 공개하고, 다른 사람은 총액만 보인다 (10/3)
- **고정비(월세·통신비)** 🟢: 사용자가 "제외" 버튼으로 직접 뺀다
- **순위** 🟢: 사용률(쓴 돈 ÷ 예산)이 낮은 순. 1 · 2 · 3등은 금 · 은 · 동(또는 왕관)으로 강조한다 (10/3)
- **기술 스택** 🟡: FastAPI + HTML/JS + 외부 Postgres, Render 배포 (제안. 팀장이 뼈대를 만들면서 확정해 공유한다)

## 1. 문제 정의 🟡

- **누가**: 용돈·알바비로 한 달을 사는 대학생
- **언제 (막히는 순간)**: 월말이나 시험 기간에 돈이 떨어졌을 때
- **지금은 어떻게**: 혼자 가계부 앱을 쓰다 며칠 만에 그만두거나, 단톡방에 지출을 인증한다 (합계가 안 남음)
- **그 비용**: 다짐만 하고 실천으로 이어지지 않은 팀원 경험 (예: 일주일 예산 계획 = 학식 × 2 × 날짜)

## 2. 타깃 사용자 🟡

- 22세, 자취하는 3학년, 용돈 + 알바, 체크카드와 토스 사용

## 3. 솔루션 한 줄 🟡

- 친구들과 목표를 공유함으로써 달성 의욕을 높인다

## 4. 핵심기능 1개 🟡

- **입력**: 참여할 때 고른 가짜 은행 계좌의 거래내역 + 항목마다 "몇 명이서"와 "제외"
- **처리**: 출금만 지출로 바꾼다. 금액 ÷ 인원을 내 지출로 더해 예산에서 뺀다
- **출력**: 기간 중에는 본인 페이지의 목표까지 남은 금액, 마감일에는 결과 카드의 순위
- **확장 기능 (10/8 이후)**: 실제 계좌 연결 · 금액 카테고리화 · 결과 카드 이미지 공유 · 또래 평균 예산 · 대결 구조 확장

## 5. 범위 밖 🟡

- 실제 계좌 연동 (오픈뱅킹, 마이데이터, 토스 등). 이번에는 **가상 계좌**만 쓴다
- 지출내역 캡처(스크린샷) 인식
- 수익화 (배너 광고)
- 회원가입 (방마다 닉네임 + 숫자 4자리로 다시 들어오기만 있다. 이메일 · 전화번호 · 실명은 받지 않는다)
- 앱 (웹만)
- 실제 돈 걸기 (내기·송금)
- 거래 항목을 친구에게 공개
- 기간 중 실시간 팀 비교 (발표에서 "추후 구현"으로 소개)

## 6. 필요 데이터 🟡

| 데이터 | 출처 | 어디에 쓰나 | 확인 |
|---|---|---|---|
| 가짜 은행 거래내역 | 팀이 직접 만든 예시 데이터 (`app/expenses/mockbank/`) | 지출 입력 | 작성함 (계좌 3개) |
| 방 · 멤버 · 지출 저장 | 외부 Postgres | 남은 예산 보드 | 생성 전 |
| (선택) 은행 거래내역 파일 | 팀원이 자기 은행 앱에서 내려받은 엑셀 | 실제 지출 입력 시연 | 은행과 양식 확인 전 |

- 외부 API와 외부 공공 데이터는 필요 없다. 인증키도 없다.
- 가상 계좌는 실제 데이터가 아니다. 화면과 발표에서 "가상 계좌"라고 밝힌다.
- 가짜 은행 거래 날짜는 시연 주(10/2 ~ 10/8)로 고정한다 (10/3). 데모 방도 같은 기간이다. 오늘 이후 거래는 아직 안 일어난 것으로 보고 돌려주지 않는다.
- 파일 업로드를 만들 경우: 파일은 읽은 뒤 버리고 저장하지 않는다. 실제 거래내역 파일은 이 레포에 올리지 않는다 (공개 레포).
- 친구에게는 합계와 남은 예산만 보인다.

가상 거래내역에 넣을 시연 시나리오: 학생식당 결제, 같은 결제 두 번(중복 경고), 택시 가승인, 충전, 내 계좌 간 이체, 입금, 기간 밖 날짜, 여럿이 같이 낸 식비(몇 명이서 선택용), 월세나 통신비(제외 버튼용).

## 7. 성공 지표 🟡

후보 (핵심 1개와 baseline을 골라야 함):

- 1주 챌린지에서 5명 중 4명 이상이 마감일까지 항목 조정을 마친다 (미확인 없이 결과 확인)
- 목표 금액을 입력받고 목표 날짜까지 데이터가 유지된다 (DB)

baseline 후보: 사전 질문 "혼자 가계부를 1주 넘게 쓴 적 있나" 인원, 또는 단톡방 수동 챌린지 제출 인원. 10/8 전에는 1주만 잴 수 있다.

보조 지표 후보: 방 만들기 → 참여(은행 연결 → 내 계좌 선택) → 불러오기 → 조정 완료까지 걸린 시간.

주의: 1주 챌린지의 실제 지출은 가상 계좌로는 넣을 수 없다. 직접 입력(예비)이나 파일 업로드(선택)로 넣거나, 단톡방과 스프레드시트로 따로 잰다.

## 8. 기대 효과 🔴

- **사회적 임팩트**: 혼자서는 이어 가지 못하는 지출 관리를 친구와 함께라서 이어 간다
- **인구구조 위기와의 연결 (추후 연계, 🟡 제안)**: 자취하는 대학생은 1인 가구다. 혼자 사는 사람이 늘어나는 인구구조 변화 속에서, 혼자서는 이어 가기 어려운 지출 관리를 또래와 함께 이어 가게 한다. 같은 방 구조를 다른 세대의 1인 가구(예: 은퇴 후 고정 소득으로 사는 사람)로 넓힐 수 있다
- **근거 (출처 URL)**: 아직 없음. 1인 가구 통계는 출처를 확인한 뒤 넣는다

## 사용 흐름

1. **방 만들기**: 기간을 정하면 링크가 생긴다
2. **참여**: 링크를 열면 참여자 이름이 보이고, 그 자리에서 닉네임 · 내 예산 · 숫자 4자리를 넣고 은행 연결 → 내 계좌 선택(가짜 은행 화면 안)을 한다 (로그인 없음, when2meet 참고). 다른 브라우저에서 열면 내 이름을 누르고 4자리를 넣어 다시 들어온다
3. **본인 페이지**: 내 계좌의 거래내역을 불러오고, 목표까지 남은 금액을 본다. 그만두려면 항복 버튼
4. **조정**: 불러온 출금 목록에서 항목마다 "몇 명이서"와 "제외"를 고르고 조정 완료를 누른다 (안 하면 미확인)
5. **결과 카드 (마감일)**: 순위(금 · 은 · 동) · 초과 · 미확인 · 항복 깃발. 다른 사람은 총액만

## 거래내역 처리 규칙

- 출금만 읽고 입금은 무시한다. 정산받은 돈은 "몇 명이서" 선택으로 이미 처리된다
- 가승인 결제는 자동으로 제외한다 (택시처럼 같은 출금처로 두 번 적히는 경우)
- 항목마다 "제외" 버튼을 둔다. 내 계좌 간 이체와 충전은 자동으로 제외 후보로 표시한다
- 기간 밖 날짜는 자동으로 제외한다
- 날짜 · 상호 · 금액이 같으면 중복 경고를 띄운다
- 이미 저장한 거래는 다시 불러와도 두 번 저장되지 않는다
- 친구에게는 합계와 남은 예산만 보인다. 거래 항목은 보이지 않는다

## 시연 (10/3)

- 범위: 지출이 올라옴 → 1/N · 제외 반영 → 최종 결과 카드
- 데모 방: 발표자(가짜 은행 계좌 A) + 총액만 있는 3명 + 중도포기 1명
- 참여자 시점: 발표자가 불러오기 → 조정 → 결과 카드까지 클릭으로 간다
- 개발자 시점: 마감 전이라도 결과 카드를 보는 시연용 옵션(`?preview=1` 같은 것)
- 관객: QR로 데모 방에 들어와 닉네임 · 예산을 넣고 참여한다 (계좌는 기본값으로 미리 골라 둔다)
- 곁가지 장면은 사진 · 짧은 영상으로 발표자료에 넣는다

## 실제 서비스로 가는 길 (발표용)

- 오픈뱅킹은 핀테크 사업자와 전자금융업자만 이용할 수 있다. 팀이 직접 신청했고 자격 요건으로 거절되었다 (10/2).
- 그래서 지금은 오픈뱅킹 명세(거래내역조회 · 잔액조회 · 사용자인증 흉내)를 그대로 본뜬 가짜 은행으로 시연한다. 토큰 인증만 생략했다. 허가가 나면 주소만 바꿔 끼우면 같은 방식으로 동작한다.
- 서비스화 단계에서는 사업자 등록 후 이용기관으로 신청하거나, 승인된 사업자의 계좌 조회 API를 계약해 실제 계좌와 연결한다. 세부 요건은 금융결제원과 핀테크지원센터에서 확인해야 한다.
- 확인 화면, 제외 규칙, 보드는 데이터가 어디서 오든 그대로 쓴다. 바뀌는 것은 "거래내역을 불러오는 부분" 하나다.
